# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

LCN (Logical Credal Networks) is a Python library for probabilistic logic that combines propositional logic with imprecise probability bounds. An LCN program specifies constraints like `0.3 <= P(A | B) <= 0.5` over propositional formulas, defining a set of probability distributions. The library provides exact and approximate inference algorithms for marginal queries and MAP/MMAP explanations.

## Build & Development Commands

The package is built with the **hatchling** backend and is installable with **uv** (recommended) or plain `pip` (requires Python 3.12+; numpy/scipy/networkx no longer support older versions). Core deps are numpy, scipy, networkx, pyomo, pyagrum, tqdm, matplotlib; `pandas` is the `experiments` extra, `ipykernel` the `notebooks` extra, and `pytest`/`pandas`/`ipykernel` are in the uv `dev` group (installed by `uv sync`).

```bash
# Recommended: uv (creates the venv and installs from uv.lock)
uv sync
uv run pytest tests/                 # run the test suite
uv run python lcn/inference/marginal/exact.py   # run a module demo

# Alternative: pip in a conda env
pip install -e .
pytest tests/

# Single test / specific test
pytest tests/test_mixed_graph.py
pytest tests/test_mixed_graph.py::TestClassName::test_method -v
```

**External dependency:** The `ipopt` nonlinear solver is required at runtime. Install via `brew install ipopt` (macOS) or build from source via `coinbrew` (Linux). The local install is `ipopt 3.14.19` with **MUMPS only** (no HSL/pardiso/spral), so `linear_solver` is not a tuning lever.

**Optional solver:** `scip` (`brew install scip`, local install 10.0.2) is an optional *global* solver used **only** by the verifier `lcn/inference/marginal/verify_scip.py`, which Pyomo drives via its AMPL/NL interface (`SolverFactory('scip')`). It is not needed by the core inference engines. Being a spatial branch-and-bound global solver on a nonconvex bilinear problem, it certifies some marginals fast (e.g. alarm C/D) but may hit the per-solve time limit on harder atoms — the verifier reports `CERTIFIED`/`PARTIAL`/`UNSOLVED` with the optimality gap.

**Lint:** `uvx ruff check <path>` (ruff is not a declared dependency; run via `uvx`).

## Architecture

### Core Model (`lcn/core/`)
- `model.py` — `LCN` (main model class; load via `l = LCN(); l.from_lcn("file.lcn")`), `Sentence` (Type1 `P(φ)` / Type2 `P(φ|ψ)` with lower/upper bounds), `Formula`, `Atom`. The LCN builds a **primal graph**, **structure graph**, and derives **independence assumptions** via the Local Markov Condition (`local_markov_condition()`).
- `parser.py` — parses propositional formulas. Operators: `and`/`&`, `or`/`|`, `xor`/`^`, `nand`/`/`, `not`/`!`. Uses `json_schema.py`.
- `independencies.py` — `Independencies` / `IndependenceAssertion` (conditional independence statements; `event1=X`, `event2=Y`, `event3=S` for `X ⟂ Y | S`).
- `mixed_graph.py` — `MixedGraph` (directed + bidirected edges) for deriving Markov conditions.
- `plotting.py` — `plot_graph(G)`: static matplotlib/networkx drawing of a primal graph (`nx.DiGraph`) or structure graph (`MixedGraph`; undirected edges drawn without arrowheads), honouring node/edge `color` and node `shape`. Replaced `gravis` (dropped: unmaintained, needed `pkg_resources`/`setuptools<80`) in the demo notebooks.

### Inference (`lcn/inference/`)

All inference algorithms use **Pyomo** to formulate optimization problems solved by `ipopt`. The marginal NLPs are **nonconvex** (conditional-probability ratios + quadratic Markov equalities), so ipopt is a *local* solver — see the gotchas in the [[ipopt-config-shared]] and [[exact-not-a-reliable-oracle]] memories.

**Marginal inference** (`lcn/inference/marginal/`):
- `exact.py` — exact marginal inference over the full 2^n joint; `ExactInference.run(..., mode="exact"|"fast")`.
- `ariel.py` — ARIEL message-passing (approximate) over a factor graph; also has a factor-graph + independence-assumption analysis (`ArielInference.analyze()`).
- `sccp.py`, `sccp_ariel.py` — SCC factor-graph propagation (see [[sccp-algorithms]]).
- `cn/` — the **credal-network family** (compile to a credal net, enumerate extreme points): `cve.py` (Credal Variable Elimination — the hub, see below), `pair_potentials.py` (its potentials), `factorization.py`, `ivbp.py` (Interval Belief Propagation, class `IntervalBP`), `approxlp.py` (ApproxLP, reported as CDVE), `cjt.py` (Credal Junction Tree, below). `cve.py` requires the optional `pyagrum` dependency. CCTE and IJGP were **removed** (not correct); do not reintroduce them.
  - `credal_network.py` — `CredalNetwork` (the compiled credal net: chain-graph factorization + **interval** local credal sets P(child|parents), pyAgrum-free); `from_lcn(..., n_jobs=K)` computes the per-family interval solves in parallel on a `ThreadPoolExecutor` at **per-solve granularity** (each individual min/max solve is one task; order-preserving, numerically identical to serial). Threads (not processes) because ipopt runs as a GIL-releasing subprocess — this fixes an earlier `ProcessPoolExecutor` hang (the SLSQP-isolation `fork` nested inside a pool worker on Linux) and drops the K× interpreter-memory cost; the threaded branch forces `LCN_ISOLATE_SLSQP=0` so no fork happens under threads. `save_cn`/`load_cn` serialize it to a portable JSON `.cn` (intervals only, plus a `compile_time` and `(method,merge_budget,solver)` provenance header; extreme points are re-derived on demand by `CredalNetworkVertices`). `cn_metadata(path)` reads just that header for cache checks.
  - `compile_cn.py` — the **compiler CLI**: compiles a `.lcn` into its credal network and writes a `.cn` alongside the input (same basename). `python -m lcn.inference.marginal.cn.compile_cn foo.lcn [--n-jobs K] [--method linear|linear-tight] [--solver ipopt|scip] [--merge-budget N] [-o OUT.cn]`.
  - **`.cn` cache** — `CredalNetworkVertices.from_lcn(..., lcn_file=<path>, cache=True)` transparently loads a compiled `.cn` next to the `.lcn` instead of re-solving, **iff** its recorded `(method, merge_budget, solver)` match the requested build (`n_jobs`/`compile_time` are not part of the key); on a hit the reported `build_time` reuses the stored `compile_time` plus local vertex-enumeration. Disabled for CredalJT (`solve_families=False` carries no cacheable intervals). In the experiment runner this is the **`compile` stage** (`experiments/run_algorithm.py --stage compile`, batch via `run_experiment.py --stages compile`): it writes a `.cn` per instance recording `compile_time`; all other credal-net algorithms then auto-load it. Both runners surface `--n-jobs` (parallel per-family solves) and `--no-cache` (force recompute).
  - **`.vtx` cache (LRS vertices)** — the second, higher layer: `CredalNetworkVertices` also serializes the enumerated extreme points to a JSON `.vtx` (same basename: `foo.lcn`→`foo.cn`→`foo.vtx`) via `save_vtx`/`vtx_metadata`/`load_extreme_points`, recording `enumeration_time` (LRS wall-clock) and carrying `compile_time` through, keyed by the same `(method, merge_budget, solver)`. `from_lcn` checks the `.vtx` **before** the `.cn`: on a match it skips BOTH the per-family solves and LRS (loads vertices; rebuilds only the cheap chain-graph *structure* for `cnv.cn`/`bn_min`, recompiling the `.cn` structure-only if absent so a `.vtx` is usable standalone), and reports `build_time = compile_time + enumeration_time`. The LRS enumeration runs **serially** on the monolithic `gum.CredalNet` — it is *not* parallelized: LRS is cheap (treewidth-bounded, see `docs/lrs.tex`) and pyAgrum's `intervalToCredal()` both holds the GIL and is not thread-safe (aGrUM vendors classic `lrslib.c` with shared file-scope globals), so a former per-node `ProcessPoolExecutor` was pure overhead (~11× slower than serial) and a hang source; `--n-jobs` therefore affects only the compile per-family solves, not enumeration. In the runner this is the **`enumerate` stage** (`--stage enumerate`); engines surface `loaded_vertices_from_cache`/`enumeration_time`.

- **`cve.py` — CredalVE** over **pair potentials** (`pair_potentials.PairPotential`: dense `(m, *cards)` arrays `P`, `Q`; Mauá & Cozman 2020 Alg. 2), exact under evidence. One elimination per credal-net **node** with the node last (pairs stay `p == q` until the query `{(1-t, t)}` enters at the end), shared by all its atoms (compound atoms via indicators — no singleton LP). Prunes: exact **Pareto** in both orders (`prune("both")`, final step only); exact **convex-hull / ray** pruning of query-free potentials (`prune_query_free` → `hull_vertices`: SVD affine projection, closed form for dim ≤ 1, qhull to dim 7 and ≤ 5000 rows, Clarkson LP test `_lp_hull_vertices` above that for ≤ 1000 rows, else keep all — keeping is always sound); hash-based dedup after every product (`_first_unique_rows`; `np.unique(axis=0)` was 80% of run time). Query-free pairs are **rescaled** to max 1 in `prune_query_free` (`normalize`; ratio-invariant) and the zero-pair test is **exact** (`_ZERO_TOL = 0.0`) — a positive threshold made every answer vacuous once P(e) < 1e-15 (60 evidence atoms on tree n100). `build_cpt_pairs` raises on a missing parent configuration (no uniform fallback). Exact CVE solves all 10 `benchmarks/real` instances (≤ 0.3 s except tank 21 s; the old CVE timed out / OOM on 5); `examples/smokers.lcn` is still out of reach (its S|F input potential alone has 16.7M functions). **FPTAS** (`run(epsilon=E)`, Mauá–de Campos–Zaffalon 2012): `PairPotential.quotient(alpha)` (one real pair per α-equivalence class) after every product, sum-out and the query step, with `alpha = (1+E)^(1/(2N))` per node (`N` from `_count_quotients`) ⇒ **inner** bounds within a factor 1+E (proof: odds-covering lemma `lem:cover` in the paper appendix). Measured: the grid merges almost nothing at 8–16 coordinates, so the FPTAS mostly matches exact time (observed error ~1e-7); it helps on dag n10 (3.9→0.9 s). Clustering (CVE_cm/CVE_cp), the additive-ε prune and the cross-family `coupling` mode were **removed** — `run()` takes only `evidence, elim_heuristic, epsilon, verbosity`.
- **`ivbp.py` — IntervalBP**: **credal sum-product** on the factor graph (family factors f_V(V, pa V) + 0/1 evidence factors). A message is the set of **hull vertices of its normalized vectors** (`(m, k)` array; binary = an interval, i.e. the factor-graph form of 2U). Updates: var→factor = elementwise product of the other incoming sets (`_product`, normalize, hull-reduce); factor→child = per parent-corner Minkowski sum of weighted row-vertex sets (`_factor_to_child`, no vertex-combination enumeration); factor→parent = per corner of (child λ, other parents) the box `[Σ w·min⟨λ,row⟩, Σ w·max⟨λ,row⟩]` per parent state, normalized box corners (`_factor_to_parent`). All updates are projective in each input, so hull vertices are lossless ⇒ **exact on polytree credal networks (binary AND compound/multi-valued), with or without evidence** (verified vs brute force / CVE, incl. compound middle and compound parents: `examples/ivbp_compound_{mid,parents}.lcn`); alternating forward/reverse sweeps until no change (certifies the fixed point). Loopy: same sweeps to `threshold`/`n_iters`, no guarantee. Flags `exact`, `singly_connected`, `converged`, `iterations` (harness: `ivbp_exact`, `ivbp_converged`, `ivbp_iterations`). Compound atoms are read off the belief vertices (no LP). `method="variational"` (mean-field) and the Pyomo singleton LP were **removed**. Note: some shipped `polytree_*_fr` instances (e.g. `polytree_fr_n20_1`) compile to a **loopy** credal network, so IVBP is not exact on them.
- **`approxlp.py` — ApproxLP (reported as CDVE)**: coordinate descent over the local credal sets, one **family** at a time. Per family, one VE of all other factors (+ evidence masks) onto `{V} ∪ pa(V) ∪ {Q}` gives `P(·, e) = Σ P(x|π) T(x,π,Q)`, and the step solves the family's linear-fractional program **exactly by Dinkelbach** (every row picks its best vertex independently; `_family_step`). Objective is **per atom** `P(a=1|e)` (compound atoms included; evidence keyed by atom → state masks). Barren families (not ancestors of query ∪ evidence) are pruned. Starts: centroids (with a one-time tie move to vertices to escape the symmetric saddle) + `n_restarts` random vertex starts (default **8**, harness `--n-restarts`, suffix `_r{R}`). Always **inner** (every visited point is a member of P_SE with P(e) > 0). Measured on 63 small cases with/without evidence: old mean gap 0.022 / worst 0.987 / 6.0 s (crashed on compound-atom evidence) → new R=8: mean gap 0.0000 / worst 0.000 / 2.0 s; n=100 trees ≈ 3.5 s. The D4 `coupling` mode and the Pyomo singleton LP were **removed**.
- **`cjt.py` — CredalJT** (harness: `--algorithm cjt`, `--solver scip` default / `ipopt`), the exact cluster-marginal NLP. Exactness (H1–H4 of `thm:d5`) hinges on the **LMC triage**, which was rewritten after a soundness review (`docs/research-chain-lcn/iclr2027/revision_plan.md`):
  - Two candidate trees; the narrowest one on which H3 holds wins. **Ordered** (`_JTClusters(order="topological")`): eliminate the chain-graph node DAG in reverse topological order and impose one row `x ⟂ N_x∖pa(x) | pa(x)` per node (`_triage_ordered`) — these imply every LMC assertion via the DAG factorization, so H3 holds by construction with no widening. It is rejected if a row isn't entailed by a single LCN assertion or an LCN assertion splits a compound node (e.g. `smokers`). **Min-fill** (`_triage_lmc`): reduce each assertion exactly against G* (`reduce_assertion`: keep only `Y ∩ reachable(X, G*∖Z)`), host, widen by the reduced scope to a fixed point within the budget, else **relax** to hostable pairwise consequences (sound, outer, H3 fails).
  - Do **not** reintroduce the two old bugs: dropping unhostable assertions ("strong extension satisfies every LMC" is false for CJT), and treating `X ⟂ Y | Z` as entailed via a tree separator `S ⊋ Z` (only `separates(X,Y,Z)` — graph separation by Z itself — is sound).
  - SCIP endpoints: certified iff proven optimal or `|primal−dual| ≤ cert_tol` (1e-4); otherwise the **dual bound** is reported (sound outer). Never report an unfinished incumbent.
  - **Conditional queries** P(a|e) are solved in **Charnes–Cooper form** (`_build_constraint_model(..., evidence=...)`: y = r·q, simplex rows Σy = r, Type-1 bounds scaled by r, **marginal-form LMC rows P(x,y)=P(x)P(y) scaled to r·⟨A_a,y⟩ = ⟨A_b,y⟩⟨A_c,y⟩** (every row must be made homogeneous — missing this made the scaled program infeasible or forced r=1), one row ⟨A_e, y⟩ = 1, linear objective ⟨A_{a∧e}, y⟩). SCIP `infeasible`/`unbounded` results (±1e20 sentinels) are never certified or returned; any non-probability value is rejected (`_is_prob`). Do **not** go back to an auxiliary t with a P(e) ≥ ε floor: at ε = 1e-6 the ratio equality is within SCIP's feasibility tolerance for every t (`examples/cjt_zero_evidence.lcn` gives [0,1] instead of [0.2,0.4]). When a query and the evidence share no cluster (H4), `CredalJT._augmented_atom` builds a tree augmented by their node set (`route == "augmented"`); the direct 2^n local fallback (`"direct-local"`, uncertified) is only for over-budget trees. `CredalJT` exposes `h3`, `d5_exact` (structural), `certified`, `exact`, `solve_status`, `atom_status`; the runner logs them as `cjt_h3`/`cjt_certified`/`cjt_exact`/`cjt_solves`. `examples/cjt_dropped_lmc.lcn` is the regression instance (exact `min P(x3)=0.022727`).

**MAP inference** (`lcn/inference/map/`):
- `exact_map.py` — exact MAP/MMAP via DFS / Limited Discrepancy Search / Simulated Annealing. Scores configurations with `solve_exact_model` (defined here; query-bound NLP).
- `approx_map.py` — approximate MAP/MMAP via AMAP (uses `ariel.ArielInference`), approximate LDS, or approximate SA.

**Shared utilities** (`lcn/inference/utils/`):
- `common.py` — the shared toolbox: `make_ipopt(debug, mode)`, `check_consistency`, `make_conjunction`, `eval_indicator`/`dot` (Pyomo indicator/expression helpers), `build_truth_table`/`conjunction_indicator`/`lmc_constraint_groups`/`lmc_constraint_groups_vec` (LMC constraint construction), `find_feasible_points`/`optimize_marginal_slsqp` (SLSQP fallback), `check_consistency_product_witness`.
- `factor_graph.py` — `FactorGraph`, `VariableNode`, `FactorNode`, `FactorGraphEdge`.
- `convert_uai_to_lcn.py` — UAI → LCN conversion.

There is **no** `lcn/inference/legacy/` package — it was removed; the active engines are the ones above.

### Experiments (`experiments/`)
- `run_algorithm.py` runs one algorithm on one instance; `run_experiment.py` runs a set over a benchmark directory. **Algorithms:** `exact` (2^n joint), `ariel`, `cjt`, `ivbp`, `cve`, `approxlp` — nothing else. **Variants are flags, not names:** `--solver scip|ipopt` (exact, cjt; default scip = certified), `--epsilon E` (cve FPTAS, inner bounds within a factor 1+E; clustering CVE_cm/CVE_cp was removed), `--n-iters` (ivbp/approxlp/ariel), `--cert-tol` (cjt). The credal-network build solver is `--cn-solver` (not `--solver`). Build stages run with `--stage compile|enumerate` (`--stages` in the batch runner).
- Output files are `results/{benchmark}/{algorithm}{variant_suffix}.jsonl` (`variant_suffix` in `run_algorithm.py`, e.g. `cve_e0.1`, `cjt_ipopt`); each record carries `variant`. With `--verbosity 0`, `run_algorithm.py` prints exactly one JSON document on stdout (library output goes to stderr, at fd level so the time-limit subprocess is covered).
- `analyze_results.py --reference RUN` (default `cjt`) scores runs by run name (algorithm + suffix); for `cjt`/`exact` only **certified** endpoints are compared (`cjt_solves[].certified`, `exact_status`). Exact engines are never scored as approximations.
- `results_legacy/` holds the pre-revision logs (old names, uncorrected CJT reference) — never use them as a reference.

### Generator (`lcn/benchmarks/`)
- `generator.py` — `Generator` class for random LCN instances (chain/dag/polytree/tree/ktree/random topologies). `generate(..., consistency_mode="product"|"full")` rejection-samples consistent instances; `"product"` (default) uses a fast, sound product-distribution witness check that guarantees consistency for n ≤ 10.
- **`ktree` topology** — the maximal graph of treewidth exactly `k` (Arnborg–Proskurowski): start with a `(k+1)`-clique, then attach each new vertex to an existing `k`-clique. Rendered as a DAG (`_graph_ktree`) so every atom conditions on the **full conjunction** of its `k` clique-parents (via `_build_lcn(full_parents=True)`); the moralized/atom graph then has treewidth exactly `k`, letting inference scaling be studied against treewidth rather than raw `n`. The `k` parameter is a `generate(..., k=…)` arg and the `--k` CLI flag; requires `n ≥ k + 1`; `k=1` is a random rooted tree. **`ktree-fr`** is the same topology with extra marginals restricted to root atoms, so it has no non-family-realizable *sentence* — **but** for `k ≥ 2` a k-tree is not singly-connected (loopy after moralization), so unlike `tree-fr`/`polytree-fr` this does **not** make Credal VE / Interval BP exact (a *structural* non-realizability the extras placement can't fix; use CredalJT / `ExactInference(solver="global")`). CLI: `--family-realizable` on `gen_ktrees.py` or `--types ktree-fr` on `gen_benchmarks.py`.
- **`dag` topology** — a random DAG with **user-tunable in-degree** (`--max-parents`, default 2, no upper cap; `_graph_dag` guarantees DAG-ness by drawing parents only from earlier vertices in a random ordering). Unlike `ktree` (treewidth *exactly* `k` by construction), the DAG is **unstructured** and its moralized chain-graph treewidth is bounded *above* by `max_treewidth` (default 4, `--max-treewidth` CLI) via **rejection sampling**: candidates whose `moralized_treewidth(scopes)` (module-level min-fill helper, same algorithm as the engines' induced-width) exceeds the cap are resampled — this bound holds regardless of `max_parents` (higher fan-in just rejects more candidates). Accepted scopes still go through the standard product-witness consistency check, so a `dag` instance is both treewidth-bounded and consistent. **Caveat:** rejection sampling does not scale — measured acceptance at `max_parents=2`, cap 3 is 99% at n=10, 60% at n=20, 17% at n=30, **0.6% at n=50** (and 0% at n≥30 for `max_parents=3`), so plain `dag` is effectively ungeneratable past n≈30. Use `dag-fr` for large bounded-width DAGs.
- **`dag-fr` topology** — the family-realizable DAG class (`_graph_dag_bounded`), differing from `dag` in two ways. (1) **Treewidth by construction:** each vertex's parents are a random *subset* (size `1..max_parents`) of a randomly chosen `k`-clique of an underlying **partial k-tree** (`k = max_treewidth`), so every family's moralized clique sits inside a `(k+1)`-clique of that k-tree ⇒ the moral graph is a *subgraph* of a k-tree ⇒ treewidth ≤ `k` regardless of `n`. The `moralized_treewidth` rejection check is retained only as a cheap safety net (min-fill is an *upper* bound and can overshoot by one). This is what makes n=50/100 bounded-width DAGs generatable at all. Because parents are a *subset* of the host clique (mean in-degree ≈1.5 at `max_parents=2`), the result stays genuinely unstructured and sparser than a `ktree`. (2) **Family-realizable:** extras on root atoms only *and* `full_parents=True`. It draws 1–3 roots (not 1) precisely so the root-only extras have more than one atom to land on. **Caveat:** like `ktree-fr` with `k ≥ 2`, `dag-fr` is sentence-realizable but **not** singly-connected (any ≥2-parent collider moralizes into a loop), so Credal VE / Interval BP are **not** exact on it — use CredalJT / `ExactInference(solver="global")`. CLI: `--family-realizable` on `gen_dags.py` (files `dag_fr_tw{cap}_n{n}_{i}.lcn`) or `--types dag-fr` on `gen_benchmarks.py`.
- **Family-realizability has two halves** (`def:realizable`, `docs/strong_extension_exactness.tex`). `extras_on_roots_only` handles the Type-1 half (no marginal on a non-root child). The Type-2 half requires `psi` to pin **exactly one full parent configuration** — a `psi` satisfied by several parent configs (a disjunction/xor, *or a conjunction over a strict subset of the parents*) bounds a `P(parents)`-weighted **mixture** of CPT rows, so it is non-realizable even though its atoms fit the family scope. `full_parents=True` (a full conjunction of signed literals over **all** parents) is the form that satisfies it, so it is now passed for every `-fr` class with multi-parent families: `ktree-fr`, `dag-fr`, **and `polytree-fr`**. (`tree-fr` is excluded deliberately — its families have exactly one parent, so it is already realizable and passing the flag would be a no-op that needlessly perturbs its RNG stream.) This gap was real and unchecked: 19 such sentences across 16 of the 60 shipped `benchmarks/polytree_small_fr` instances, which have been regenerated (seed 42, epsilon 0.3, num-extras 2). Note the older `_non_realizable_sentences` test helper is Type-1-only and cannot see this; `_multi_config_psi_sentences` in `tests/test_generator_cross_family.py` implements the Type-2 check (it reads `Formula.atoms.**values()**` — the keys are placeholders like `V1`, so using `.keys()` silently makes the check vacuous).
- **CredalJT-exactness gate** — `generate(..., cjt_exact="structural"|"certified", cjt_max_width=12, cjt_time_limit=60)` (CLI `--cjt-exact`, `--cjt-max-width`, `--cjt-time-limit` on `gen_benchmarks.py` and `gen_{trees,polytrees,ktrees,dags}.py`) rejects candidates on which CredalJT is not provably exact, via `cjt_exactness_report(lcn)`: `structural` checks H1–H4 on the tree CredalJT builds (no solve); `certified` also requires every SCIP endpoint certified. Accepted instances carry `lcn.cjt_report`, which `Generator.save` writes as `#` header comments. Default `None` leaves the RNG stream unchanged.
- `gen_benchmarks.py` (`--max-treewidth` for dag/dag-fr), `gen_chains.py`, `gen_polytrees.py`, `gen_trees.py`, `gen_ktrees.py` (`--k` treewidth), `gen_dags.py` (`--max-treewidth`, `--max-parents`, `--family-realizable`), `gen_random.py`, `gen_easy.py` — benchmark-set generation scripts.

### LCN File Format
Programs are defined in `.lcn` files (see `examples/`). Syntax:
```
label: lb <= P(formula) <= ub
label: lb <= P(formula | formula) <= ub
```
Lines starting with `#` are comments. Each sentence requires a unique label.

## Key Patterns

- Inference algorithms follow a consistent pattern: instantiate with an `LCN` object, then call `run()` with algorithm-specific parameters.
- **LMC independence constraints** for `(X ⟂ Y | S)` must use the *joint* factorization `P(x,y,z)·P(z) = P(x,z)·P(y,z)` over **all** configurations of the Y block (built by `lmc_constraint_groups`/`lmc_constraint_groups_vec` in `utils/common.py`). A per-element/pairwise decomposition under-constrains the model when `|Y| ≥ 2` and gives wrong (too-loose) bounds. The vectorized variant is bit-identical but avoids the `2^|Y|·2^n` `Formula.evaluate` cost.
- **Solver robustness:** ipopt alone is unreliable on the dense joint-LMC system. `check_consistency` and `ExactInference`/`solve_exact_model` back ipopt with a two-phase SLSQP fallback (`find_feasible_points` → `optimize_marginal_slsqp`). Use `make_ipopt(mode="fast")` only for feasibility-style solves whose result is re-verified.
- The `docs/` directory contains LaTeX algorithm descriptions (`.tex`) and corresponding PDFs — consult these for mathematical details of specific algorithms.
- The `examples/` directory contains `.lcn` files (asia, alarm, cancer, smokers, new/new2/new3, factual); larger benchmark sets live under `benchmarks/{chain,dag,polytree,...}/`.
- **Shipped family-realizable benchmark sets** follow a `{topology}_{small,large}_fr` convention with **10 instances per size**: `small` = n ∈ {5,6,7,8,9,10}, `large` = n ∈ {10,20,30,40,50,100}. Generated with seed 42, epsilon 0.3, num-extras 2. Present: `tree_{small,large}_fr`, `polytree_{small,large}_fr`, `ktree_{small,large}_fr` (k=3), and `dag_{small,large}_fr` (treewidth cap 3, ≤2 parents; files `dag_fr_tw3_n{n}_{i}.lcn`). All 480 instances (8 sets × 60) satisfy **both** halves of family-realizability and are consistent. Note `dag_*_fr` and `ktree_*_fr` are loopy, so Credal VE / Interval BP are outer-only on them — so use **CredalJT** (`--algorithm cjt`, SCIP) as the default engine there. (The old single-function CVE stalled in `Potential.prune` on loopy DAGs; the pair-potential CVE runs ktree k=3 / dag n=10 in ≤ 4 s.)
